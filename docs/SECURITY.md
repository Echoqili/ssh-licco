# 安全边界与加固配置

本项目可执行远程命令、修改远程文件。安全检查用于减少误操作，不构成远程 shell 沙箱。
远程账号的操作系统权限仍是最终权限边界。建议使用专用的非 root 账号，按任务授权，
通过远程目录权限、容器或 SSH 服务端限制控制可访问范围。

## 本次行为变更

- `ssh_connect` 默认 `accept_new_host_key=false`，严格验证已信任的主机密钥。
  请通过可信渠道核对服务器指纹，并预先配置 `~/.ssh/known_hosts`，
  或传入 `known_hosts_path`。密钥变更时应核查原因。
  显式开启自动接受未知密钥会削弱首次连接的身份校验；已有密钥仍会加载并检查。
- `confirm_dangerous` 只表示确认操作风险，不能绕过命令白名单、语法检查或硬拦截。
  该参数由调用方提供，不能当作独立的人类审批记录。
- `strict` 使用较小的基础命令列表，默认不开放 shell、解释器、构建器等通用执行工具。
  如确有需要，由操作者配置 `SSH_EXTRA_ALLOWED_COMMANDS` 或白名单文件。
  添加 `bash`、`python` 等会扩大执行权限；`balanced` 和 `relaxed` 仍允许广泛运维操作。
- `balanced` 也会拒绝换行、回车和 `&` 命令分隔。需要后台执行时使用工具的
  `background` 参数。
- 本地上传源和下载目标使用独立的 `SSH_LOCAL_BASE_DIR`，默认当前工作目录。
  相对本地路径按此目录解释；解析符号链接后越界的路径和凭据目录会拒绝访问。
- Unix SFTP 路径在远端规范化后检查：`strict` / `balanced` 限于 `SSH_BASE_DIR`
  （默认 `/home`），所有模式均保护系统敏感路径与 `.ssh` 目录。
  校验失败会终止操作。`SSH_BASE_DIR` 是 Unix 路径配置，不是 Windows ACL。
- `remote_copy` 强制检查目标主机密钥，端口限整数 1–65535，目标路径限简单绝对路径。
  不再支持通过 `target_password` 把密码放入 `sshpass` 命令行；请在源服务器配置密钥认证。
  源服务器也需要预先信任目标主机。该操作由源端 scp/rsync 执行，不能提供与 SFTP 相同的
  路径隔离保证；对非可信来源不要开放服务器间复制。

## 示例

```json
{
  "SSH_SECURITY_LEVEL": "strict",
  "SSH_BASE_DIR": "/home/deploy/app",
  "SSH_LOCAL_BASE_DIR": "D:/transfers"
}
```

上述环境变量放在 MCP 启动配置的 `env` 中。主机密钥参数通过 `ssh_connect` 提供，
不通过环境变量设置。启用严格模式后，部署、Docker 和其他写操作可能需要显式扩展白名单。

## 验证与限制

回归测试使用模拟 SSH/SFTP，覆盖确认参数绕过、命令分隔符、目录边界、敏感路径、
远程符号链接、本地目录隔离和端口注入。测试不访问真实服务器。
符号链接检查与实际文件操作之间仍可能发生竞态；应以文件系统权限和专用传输目录限制
非可信进程改写路径。命令黑名单不能穷举编码、解释器及脚本中的所有行为。

CI 在 pull request 和推送时运行测试及 `pip-audit` 依赖检查。
MCP Market 的评分依据和刷新时间由平台控制；本地测试通过不代表平台已重新评分。

## 报告漏洞

请勿在公开 Issue 中提交密码、私钥或可攻击真实主机的细节。
优先使用仓库的 GitHub 私密漏洞报告入口（若已启用），否则先联系维护者确认私密沟通方式。
